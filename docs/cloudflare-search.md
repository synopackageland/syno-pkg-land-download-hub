# Browser-assisted search

Install [Remote Tab Opener](https://chromewebstore.google.com/detail/remote-tab-opener-manager/gmofalnpnpcannbeieijjgpbapafneho) in the browser you use for Download Hub. Keep the extension enabled and reload the App. The search page checks both extension detection and a working tab-control response before showing **RTO ready**. No userscript, pasted code or local service is needed.

Search normally. Server-side sources return immediately. A public HTML source challenged by Cloudflare or unable to connect from the NAS shows **Needs browser**. When RTO is ready, Download Hub opens a source tab in the background, keeping Download Hub in front. On the first use of each domain, RTO displays its own permission panel: choose **Allow access to this domain**. A refusal returns `USER_CANCELLED` and stays a refusal; **Retry** starts another explicit attempt. If a site still requires verification after the initial wait, choose **Open website** to open a fresh verification tab and complete verification there. The App never brings a source tab forward automatically. Keep the App open until results return.

Results appear together with server-side results and source labels. Each source has one short state; expand it to see the reason, diagnostic code and one retry action. A connected RTO status does not imply that every domain is authorized or that every source is available. A magnet can create a download directly. For a result that points to a detail page, RTO opens that page and reads its magnet link. RTO has no public binary-file response API: if a protected page only offers a torrent file, save it yourself and use **New download → Torrent file**. Site cookies never go to the NAS.

The App uses each configured Cardigann definition's existing selectors, templates and filters, including imported definitions. It sends the displayed DOM to the same parser with network access disabled. It reads the first applicable search page; it does not pretend that one displayed page contains every page in a multi-page definition. Definitions requiring login, POST or non-HTML API responses, plus RSS/Torznab API feeds, display an explicit browser-support limitation. Their normal server-side connectors remain available.

If verification expires, a tab closes, its URL changes or RTO disconnects, retry from Download Hub. Cancel invalidates the pending token. Starting another search cancels the previous browser request. The NAS continues accepted downloads when the browser closes.

A phone browser cannot run Remote Tab Opener. On a phone, Search leaves out the sources that need the browser, unless the external solver passes them, and shows no browser guide or browser states, only one line counting the sources that work on a computer. Server-side sources search as usual.

The advanced external solver setting remains available. An empty URL disables that setting.

## RTO contract and measured limits

The integration uses the [public page bridge](https://remote-tab-opener.com/documentation/api-reference.php), with `origin: rto-page`, unique request IDs, correlated `rto-extension` replies and bounded timeouts. It uses `detect`, `listTabs`, `registerMasterTab`, `openTab` and top-level `dom.extract`; no extension internals or remotely loaded scripts are required.

RTO 8.6.0's legacy `getHtml` truncates at 5,000 characters. The App uses top-level `dom.extract` with source-defined result-container selectors, preserving the surrounding table that offline row selectors need. It strips scripts, styles, forms, executable attributes and inline state before enforcing the unchanged 256 KiB cleaned-HTML budget. Most sources retain a 256 KiB extraction budget. Kickass Torrents alone gets 512 KiB before cleanup because its result table can exceed 256 KiB; no caller can raise this above 512 KiB. The backend independently caps HTML at 256 KiB and accepted results at 100.

Up to four sources run concurrently. Background presence probes pause during active browser work, and a temporary DSM authentication failure leaves the shell available for recovery; a confirmed session refusal still signs out. Each receives its own single-use ticket when admitted and independent cancellation. A slow page has no shorter wall-clock limit than its ticket: the helper keeps waiting while the source shows its progress, until Cancel or the ticket expires. Delivery parses within the request's own deadline; when a busy NAS cannot finish in time, the ticket's token is handed back (`search_browser_busy`) and the same extracted page is sent again with backoff instead of failing. A search-state lock held by a slow writer is waited for within the request, and a request that still cannot get it reports `search_storage_busy` rather than a site timeout. Two matching cleaned observations avoid reading a partially loaded header. Each attempt uses a fresh tab key and requests a background new tab with `forceDuplicateForSameTabKey`, so RTO never adopts a browser tab already showing the same URL; a tab RTO still reports as reused is never closed. App-created tabs close by the tab ID RTO reported after extraction, errors, timeout, cancellation and disposal; late open replies are also cleaned up. A refused close is retried once after `listTabs` restores RTO's tab registry. Tabs that still stay open are counted in one line below the browser guide asking the user to close them; the next search clears it. An explicit Open website action starts a fresh ticket, focuses the source for verification and closes the App-created tab when finished.

LinuxTracker retains its default availability: its live Ubuntu catalogue provides results, while some queries currently return an explicit unavailable-catalogue notice. The exact legacy built-in definition is corrected even in a previously fetched catalogue generation; newer upstream and imported definitions are preserved. Its definition supplies a detail-page download link and reads local peer counts separately from external counts. A confirmed catalogue notice maps to a neutral No data currently state; ordinary zero matches map to neutral No results. Technical codes live inside collapsed Advanced details.

RTO controls visible, authorized tabs and the top frame only. A site may restrict it through RTO Lock. Chrome MV3 can temporarily return `BACKGROUND_NO_RESPONSE`; the App retries only bounded, observational extraction and never treats a presence probe as proof of a connected worker. RTO also publishes a Firefox extension; this integration's device acceptance targets the supplied Chrome-based Ego Browser, not an untested Firefox guarantee. See [DOM API](https://remote-tab-opener.com/documentation/dom.php) and [troubleshooting](https://remote-tab-opener.com/documentation/errors.php).

## Search ownership and migration

Only a fresh authenticated DSM caller can issue or deliver a browser request. A private token binds one batch to the caller's username/UID, SDK search job, worker attempt, source revision and exact page URL. Delivery spends the token once. Source edits, disablement, cancellation, expiry and job-state changes refuse stale deliveries. Only the configured source's declared/selected origins are accepted. DOM-provided URLs are untrusted; browser detail URLs are never fetched by the NAS, and magnets are parsed and reduced to a valid infohash plus display name.

An upgrade removes the old saved browser-clearance state and its paired User-Agent. Affected cached results expire. Obsolete cookie jobs are purged through the SDK; this clears the affected owner's transient search/probe history, including retained inputs. Existing download tasks and unrelated source credentials are preserved.

Each source keeps its own loading deadline, starting after its tab opens; queue and ticket admission do not spend that deadline. Advanced details record milliseconds for queued, open, opened, loaded, stable, extracted, delivered and closed phases, plus the triggering NAS code. Kickass Torrents may follow same-origin redirects; other sources retain exact URL checks, and cross-origin navigation is refused. Redirect diagnostics omit queries and fragments. Network reply reading runs separately from result persistence and browser planning so those operations cannot exhaust the helper network deadline.
